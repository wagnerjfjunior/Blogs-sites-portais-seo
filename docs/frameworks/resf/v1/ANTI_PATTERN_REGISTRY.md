# RESF v1 — Candidate Anti-Pattern Registry

Status: `CANDIDATE`

## Intelligence / IA
- `AP-INT-001` Invent demand from intuition without observed evidence.
- `AP-IA-001` Intentionally create multiple URLs for the same primary intent.

## SEO / Content
- `AP-SEO-001` Treat Lighthouse SEO 100 as SEO completion.
- `AP-SEO-002` Copy the highest-ranking page as a universal template.
- `AP-SEO-003` Use hidden/invisible SEO content as a strategy.
- `AP-CONTENT-001` Use the same copy model for every development.

## Schema
- `AP-SCHEMA-001` Assume more schema automatically improves ranking.
- `AP-SCHEMA-002` Fabricate offers, reviews, ratings or availability.
- `AP-SCHEMA-003` Treat FAQPage as mandatory on every SEO page.

## Linking
- `AP-LINK-001` Require every product to mechanically link to another product.

## UX
- `AP-UX-001` Treat a `FIXED` filename/patch as proof of validation.
- `AP-UX-002` Treat desktop validation as sufficient mobile validation.
- `AP-UX-003` Accumulate endless `!important` patches instead of diagnosing ownership/DOM structure.

## Conversion / Lead
- `AP-CONV-001` Assume more form complexity automatically increases lead quality.
- `AP-LEAD-001` Treat a thank-you URL/page view as the lead identity.
- `AP-SCORE-001` Copy source-project scoring thresholds into a different consumer.
- `AP-SCORE-002` Operate scoring without later business calibration.

## Tracking
- `AP-TRK-001` Regenerate an identifier server-side for the same logical event.
- `AP-TRK-002` Treat HTTP 200 as proof that event semantics are correct.
- `AP-TRK-003` Send every analytics event to advertising destinations.

## Attribution / Paid
- `AP-ATTR-001` Treat gclid observed on landing as closed-loop attribution.
- `AP-ATTR-002` Create multiple Primary conversions for the same business outcome without explicit intent.
- `AP-PAID-001` Optimize by CTR while qualified lead outcome remains unknown.

## Consent / QA
- `AP-CONSENT-001` Treat a platform consent score as legal compliance.
- `AP-CONSENT-002` Design tracking first and consent enforcement later.
- `AP-QA-001` Treat documentation as runtime proof.
- `AP-QA-002` Treat a correction as proof that the problem is resolved.

These anti-patterns are Candidate governance objects. They preserve source-project learning but remain subject to provider-local review before any future `RECOMMENDED` lifecycle transition.
