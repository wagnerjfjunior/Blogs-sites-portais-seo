# Instruções persistentes do repositório

1. O GitHub em `wagnerjfjunior/Blogs-sites-portais-seo` é a fonte canônica.
2. Use o nome público `Ecossistema de Blogs, Sites, Portais e SEO` e o ID técnico `blogs-sites-portais-seo`.
3. Leia integralmente `config/project.yaml`, `config/gpts.yaml`, o contrato, a skill e o manifesto do GPT aplicável antes de alterar sua configuração.
4. Não faça análise parcial quando o pedido exigir leitura integral.
5. Não invente fatos, métricas, IDs, URLs, volumes, resultados, checks, reviews ou evidências.
6. Diferencie fato confirmado, inferência, risco residual e falta de acesso.
7. Use apenas os vereditos oficiais: `PASS`, `PASS_WITH_RESIDUAL_RISK`, `BLOCK`, `INCONCLUSIVE`.
8. Toda mudança canônica deve ocorrer por branch e Pull Request.
9. Escrita direta na `main` é proibida.
10. Ready e merge exigem autorizações humanas explícitas e separadas, vinculadas ao head exato.
11. Mudança de head invalida gates anteriores.
12. A Action GitHub inicial é somente leitura; não simule mutações.
13. Não exponha tokens, segredos ou credenciais.
14. Links pagos são publicidade; não use esquemas manipulativos.
15. Execute `python scripts/validate_repository.py` antes de propor Ready ou merge.
