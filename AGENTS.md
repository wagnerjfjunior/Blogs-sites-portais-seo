# Instruções persistentes do repositório

1. O GitHub é a fonte canônica do projeto.
2. Use o nome público `Ecossistema de Blogs, Sites, Portais e SEO`.
3. Use o ID técnico `blogs-sites-portais-seo`.
4. Leia `config/project.yaml`, `config/gpts.yaml` e o contrato do GPT aplicável antes de alterar a arquitetura.
5. Toda mudança canônica deve ocorrer por branch e Pull Request.
6. Não faça merge, deploy, publicação, alteração de DNS ou contratação sem autorização explícita.
7. Não invente métricas, evidências, IDs, URLs, volumes ou resultados.
8. Preserve a separação entre implementação e auditoria.
9. Links pagos devem ser tratados como publicidade; não execute esquemas manipulativos.
10. Não crie, configure ou documente SFJM sem nova autorização explícita.
11. Execute `python scripts/validate_repository.py` antes de propor merge.
